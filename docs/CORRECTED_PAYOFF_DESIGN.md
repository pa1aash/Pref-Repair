# A second exogenous payoff, designed against the concavity confound

Written 2026-08-29, immediately after `docs/NULL_OPERATOR_VERDICT.md`. **No code is executed in
this document and no new number from real trace data appears anywhere below.** Every quantity used
for illustration is either an algebraic derivation or a description of a distribution's
theoretical properties, computed by hand, before any comparison against `results/main_ccei.json`
or any other real-data file is run. This is deliberate, per the operator's instruction: the design
must be committed before any result exists that could bias it toward a preferred outcome.

---

## 0. What exactly failed, restated precisely enough to design against

`docs/NULL_OPERATOR_VERDICT.md` §1C shows the original payoff reduces, exactly, to
`payoff(x_t) = 2*sqrt(s_t(1-s_t))`, a function of the expenditure share `s_t` alone, with **one
single, fixed, globally-identical maximum at `s_t = 0.5` for every trace in the entire
experiment, known in advance, with zero uncertainty, to anyone who reads `src/payoff.py`.** A
GARP-blind operator that always shrinks toward that one point, using the same L1 budget as the real
projection, out-performed the real GARP-restoring projection by more than 2x (`docs/
NULL_OPERATOR_RESULTS.md` §1). The exploitable property was not "concavity" per se — it was
**a single point, invariant across every trace, that is the provably correct direction to move
every single time.** Any fix must remove that invariance, not just swap in a different fixed
point (a different constant would be exactly as exploitable) and not just flatten the curvature
without addressing the "same point every time" property.

---

## 1. The proposed design

**A per-trace, independently and exogenously drawn Cobb-Douglas weight**, replacing the original's
fixed `alpha = 0.5`.

```
For every (model, condition, replicate) slot s (matching the granularity `src/payoff.py`
already payoff-scores at — one function applied uniformly across all T=25 rounds of that trace):

    alpha_s ~ Uniform(0.05, 0.95),  drawn i.i.d. per slot,
    from an RNG stream seeded independently of every other draw in this project
    (a fresh seed offset, e.g. `20260829_500_000 + 1000*replicate_index`, distinct from the
    budget-set seed family `20260826_000 + ...` in docs/MAIN_EXPERIMENT_PROTOCOL.md §2.1),
    generated and frozen into a manifest BEFORE any repair (real or null) is constructed for
    that slot.

payoff_s(x_t) = [ s_t^{alpha_s} * (1-s_t)^{1-alpha_s} ] / [ alpha_s^{alpha_s} * (1-alpha_s)^{1-alpha_s} ]
```

where `s_t` is the expenditure share on good A at round `t`, exactly as derived in
`NULL_OPERATOR_VERDICT.md` §1C. This is the direct algebraic generalisation of the original
formula — setting `alpha_s = 0.5` recovers `2*sqrt(s(1-s))` exactly, so this is a strict
generalisation of the existing payoff family, not a different family. In `(x_A, x_B)` terms this
is unchanged in spirit from the original: `payoff_s(x_t) = U_{alpha_s}(x_t) / U_{alpha_s}(x*_{s,t})`
with `U_{alpha_s}(z) = z_A^{alpha_s} z_B^{1-alpha_s}` and `x*_{s,t}` the closed-form Cobb-Douglas
optimum at weight `alpha_s` on that round's budget line — i.e. **the exact same
`cd_optimal_bundle(p, incomes, alpha)` function in `src/payoff.py` already implements this,
called with a per-slot `alpha_s` instead of the hardcoded `0.5`.** No new numerical machinery.

**The information barrier, which is the actual load-bearing part of this design, stated as an
explicit rule:** `alpha_s` is generated by a scoring-time-only module and is never read by
`src/projection.py` (already true, unmodified) or by any null-operator construction (a new
requirement this design adds, absent from the original, because the original's `alpha=0.5` was
public and constant so there was nothing to gain by hiding it — that is exactly the property being
removed). Both the real repair and any null repair are constructed exactly as before, from `(p, x,
incomes)` alone; `alpha_s` is consulted only afterward, by the scoring step, to compute
`delta_payoff`.

## 2. Requirement-by-requirement justification

**1. Genuinely exogenous.** `alpha_s` is drawn from a fixed, pre-registered, uniform distribution,
by a seed independent of every other RNG stream in the project (budget-set generation, model
sampling), and is never a function of `x_t`, `x̃_t`, or the projection's feasibility computation —
identical standard to the original (`docs/PAYOFF_AUDIT.md` §1-2), verified the same way: by code
inspection of what functions read what arguments, once implemented.

**2. No structural correlation with generic centering.** Partially achieved, precisely bounded, not
perfectly zero — see the self-audit below, which derives this rather than asserts it. The key
property that *is* achieved exactly: **there is no longer a single point that is correct across
traces.** Each trace's own optimum is an independent draw unknown to any operator (real or null)
at construction time. What is *not* achieved, and stated plainly rather than hidden: a residual,
quantifiable, bounded bias toward centering survives for the most extreme-share traces specifically
— derived in §4 below, not swept under the rug the way it would be if this document simply asserted
"randomising the target fixes it" without checking.

**3. Economically motivated.** `alpha` represents the relative weight a downstream evaluator places
on good A versus good B — under the original design this was pinned at "exactly equal, always,"
which is itself an unmotivated assumption (`docs/MAIN_EXPERIMENT_PROTOCOL.md` §5's own justification
for `0.5/0.5` is "the zero-degrees-of-freedom choice," a convenience argument, not an economic
one). Treating the true relative valuation as **an unknown, fixed parameter drawn from a plausible
range** — rather than assumed to be exactly `0.5` in every context — is a strictly more defensible
economic story: different budget-set contexts plausibly correspond to different relative
importances of the two goods to a downstream decision-maker, and a well-calibrated agent should be
trying to track that (unknown, but real and discoverable) valuation rather than mechanically
targeting a fixed midpoint. This is an *epistemic*-uncertainty framing — "there is a fact of the
matter about the right weight for this context, the agent does not know it exactly, and the
projection algorithm does not know it either" — which is what makes it usable as a control at all
(§5 explains why the alternative, *aleatory* framing, was rejected).

**4. Still comparable.** The null-operator-control methodology needs zero redesign. `src/
projection.py` (the real repair) is untouched — it never referenced payoff before and still does
not. The null construction in `src/null_operator.py` — shrink `x_t` toward `x*_t` by a shared
per-trace `lambda` matched to the real projection's L1 dose — is unchanged in its own logic; only
which `x*_t` the *scoring* step (not the null-construction step) uses when computing
`delta_payoff` needs to vary by which comparison is being run (§6 below). The paired statistics
(Wilcoxon, paired t-test, partial correlation controlling for the null's predicted effect) are
identical in form to `docs/NULL_OPERATOR_METHOD.md` §4 — same tests, same structure, new payoff
values plugged in.

## 3. Two alternatives seriously considered and rejected

Documented because a design this consequential should show what was ruled out and why, not just
what was picked — the same standard `docs/PAYOFF_AUDIT.md` and `docs/NULL_OPERATOR_METHOD.md` §3
held themselves to.

**(a) A per-round-random future price shock, scored as `payoff'_t(x_t) = p'_t . x_t / I_t` for an
independently-drawn `p'_t` unrelated to the round's actual prices `p_t`.** This is algebraically
*exactly* zero-bias, provably, not just approximately: expressed in share terms,
`payoff'_t(s) = I_t[rho_B + s(rho_A - rho_B)]` where `rho_A = p'_{t,A}/p_{t,A}`,
`rho_B = p'_{t,B}/p_{t,B}` — **linear in `s`, not concave**, and because `p'_t` and `p_t` are drawn
i.i.d. from the same distribution independently, `E[rho_A] = E[rho_B]` exactly by symmetry, so
`E[slope] = 0` exactly. No fixed direction of movement has *any* expected advantage, for *any*
starting share, not just an attenuated one. **Rejected anyway, for a reason that matters more than
the elegance of the zero-bias proof:** because the "correct" direction under this payoff depends
on a shock realised *after* (or independent of) any choice, **no decision procedure — rational,
GARP-consistent, or otherwise — can systematically do better than chance against it, in
expectation.** It fails Requirement 3 outright: it is not a genuine decision-quality measure, it is
a fair-coin generator dressed as one, and would make the entire dose-response test underpowered by
construction (both the real repair and any null would show a null result regardless of whether GARP
restoration does anything, because the payoff itself carries no signal about *any* systematic
strategy, not just the exploitative one). A clean zero-bias proof is worthless if it is bought by
making the yardstick unable to detect a real effect even when one exists.

**(b) A raw reference bundle `r_t`, drawn independently of that round's prices/income, scored by
distance in `(x_A, x_B)` space.** Rejected on Requirement 4 and Requirement 3 jointly: a fixed
bundle's "closeness" is not comparable across budget lines with different price ratios (the same
bundle is cheap on one line, infeasible on another), breaking the price/income-invariance property
`docs/MAIN_EXPERIMENT_PROTOCOL.md` §5 explicitly built into the original design's economic
argument (property (ii): the optimum is a function of `(p,I)` alone, so payoff is comparable across
heterogeneous budget lines). A share-based target avoids this for free, which is one more reason to
stay inside the efficiency-ratio family rather than reach for something further away from it.

## 4. Self-audit: does any fixed displacement direction or magnitude have a systematic advantage?

**Yes, partially — derived explicitly, not assumed away.** Differentiating
`payoff_s(x_t)` with respect to `s_t` at fixed `alpha_s` gives
`d(payoff)/ds = [alpha_s/s - (1-alpha_s)/(1-s)] * payoff(s)`, whose sign equals
`sign(alpha_s - s)` (algebra identical in form to `NULL_OPERATOR_VERDICT.md` §1C's derivation,
generalised from `alpha=0.5` to `alpha_s`). So **moving `s` a small step toward `0.5` raises
`payoff_s` if and only if `alpha_s` lies on the same side of `s` as `0.5` does** (i.e.
`alpha_s < s` when `s > 0.5`), and lowers it otherwise.

For `alpha_s ~ Uniform(0.05, 0.95)` and a starting share `s > 0.5` inside that interval, the
probability that moving toward `0.5` helps is `P(alpha_s < s) = (s - 0.05)/0.9`. This is **less
than 1** — a real, quantifiable improvement over the original design's deterministic 100% — but it
is **not symmetric around 50%**: it rises toward 1 as `s` approaches the edge of `alpha_s`'s own
support, and — critically — **once `s` exceeds `0.95` (outside `alpha_s`'s support entirely),
`P(alpha_s < s) = 1` exactly: moving toward `0.5` helps with certainty again, identical to the
original design's failure mode, for any trace whose observed share is more extreme than the target
distribution's own range.**

**This is the honest limitation of this design, stated plainly:** GARP-violating traces in this
project's actual data are erratic by construction — nothing rules out expenditure shares
approaching a near-corner allocation (`s` near `0` or `1`) on some rounds, and for those rounds,
this design provides **no meaningfully better protection than the original** against a
center-pulling operator, because no plausible, non-arbitrary target distribution can have support
reaching all the way to the boundary (a target distribution with mass at literal `s=0` or `s=1`
would be pathological — it would mean "the right answer is to spend the entire budget on one
good," an economically degenerate reference point to draw as if it were a normal possibility). This
is not a flaw introduced by choosing `Uniform(0.05, 0.95)` specifically; **it is a property of any
bounded, unimodal, non-degenerate target distribution** — the mathematics in the paragraph above
generalises to any distribution with a well-defined interior support, not just the uniform case,
because the qualitative fact ("almost any bounded random variable's mass sits closer to the middle
of `[0,1]` than a point right at the boundary does") is true regardless of the distribution's exact
shape.

**What this means for how the fix should be evaluated, not just declared.** This design converts a
100%-exploitable, zero-noise, fully-known confound into a **partial, share-dependent, bounded**
one that is *substantially* weaker for moderate-share traces and only marginally weaker for the
most extreme ones. That is a real improvement, not a fully solved problem, and the honest statement
of what remains is itself the deliverable of this self-audit — exactly the discipline
`docs/PAYOFF_AUDIT.md` §4 and `docs/NULL_OPERATOR_VERDICT.md` already established for this
project: state the residual confound, quantify it, and route it to an empirical test rather than an
assumption. **Part B (not run in this session) must stratify the paired comparison by baseline
share extremity (or by dose, its close proxy) to check whether the residual center-pull advantage
this derivation predicts concentrates in the high-dose tail** — if it does, that is itself
reportable, and would mean this design meaningfully helps but does not fully resolve the concern for
the highest-leverage traces.

**A note on widening or reshaping the distribution.** A version of `alpha_s` with heavier tails near
the boundary (e.g. `Beta(0.5, 0.5)`, U-shaped, still symmetric, mean `0.5`, substantially more mass
near `0` and `1` than `Uniform`) would reduce the extreme-trace gap identified above, because it
would put meaningfully more probability on "the true target is *even more* extreme than this
already-extreme observation," which is exactly the condition under which a center-pull hurts rather
than helps. This is named as a candidate refinement, not adopted as the primary design here,
because (a) `Uniform(0.05, 0.95)` is simpler to describe, generate, and audit — a virtue this
project has repeatedly favoured (plain, inspectable RNG seeding over cleverness) — and (b) whether
the refinement is *worth* the added complexity should be decided after Part B's stratified check
shows whether the extreme-trace gap actually matters in this dataset, not pre-emptively engineered
around a concern that has not yet been measured. This is the same "measure before you complicate
the design" discipline the rest of this document tries to hold to.

## 5. Is the target-generation process itself exogenous?

Yes, by construction, checked against the same three criteria `docs/PAYOFF_AUDIT.md` §1-2 applied
to the original: **(i)** `alpha_s` never depends on `x_t`, `x̃_t`, or any statistic computed from
either — it is drawn from a fixed distribution before any repair is constructed. **(ii)** It never
depends on the trace's own `(p_t, I_t)` either — unlike `x*_t` (which is a function of the budget
line, correctly so, since it must be a point on that budget line), `alpha_s` is drawn from a
distribution with fixed parameters `(0.05, 0.95)` set before data collection, independent of which
budget line happened to be drawn for that slot. **(iii)** It is not correlated with GARP-violation
status: `alpha_s` is drawn for *every* slot (both the 57 already-GARP-consistent and the 85
violating traces from the main run), before violation status is known, so there is no selection
channel through which a trace's violation status could influence which `alpha_s` it receives.

## 6. The cheating-operator question, and what Part B must test as a result

**A GARP-blind operator that knows the true `alpha_s` for a specific trace (an "oracle" operator)
would behave very differently from one that only knows `(p, I)`, and the two must not be
conflated in Part B.** An oracle operator, aiming directly at `x*_{alpha_s}`, would recover — by
construction — an even larger share of the real dose-response relationship than the original null
did against the original payoff, precisely because it has privileged information no real repair
algorithm possesses. That is expected and uninteresting as a critique of C1; it would only show
that *if* GARP-restoration secretly had access to the true per-trace valuation (it does not), it
could exploit this payoff too. **Part B's design must therefore run (at minimum) two distinct null
constructions and report them separately, not pooled:**

1. **The primary, information-fair null** — the exact same construction as `docs/
   NULL_OPERATOR_METHOD.md` §3 (shrink toward the fixed `(0.5, 0.5)`-weight optimum, matched L1
   displacement), unchanged, scored under this new per-trace-random payoff. This is the direct,
   apples-to-apples replication of Part 1's test and is the primary evidence for whether this
   design closes the gap that killed C1 the first time.
2. **An oracle upper-bound null** — shrink toward the *true* `x*_{alpha_s}` for that trace, matched
   L1 displacement, explicitly labelled as using information no real operator has, reported only as
   a ceiling/sanity check on how much a maximally-informed exploit could achieve, never as evidence
   about whether the real projection is doing something meaningful.

Reporting only (2) — or worse, reporting (2) without the label — would silently reintroduce a
version of the original failure. Reporting only (1) is legitimate but reporting both, explicitly
separated, is more informative about *how much* of any residual gap is a "hasn't fully closed"
problem versus an "impossible in principle without inside information" one.
